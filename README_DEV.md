# Заметки разработчика

Документ описывает текущее состояние исходного кода в основной линии проекта. Он заменяет устаревшие заметки, которые ошибочно описывали несколько независимых реализаций как полностью готовые и проверенные.

## Текущая основная архитектура

Рабочая точка входа — `main.py`.

- `core/state_machine.py` — класс `StateMachine`, состояния и профили ботов.
- `core/scheduler.py` — класс `Scheduler`, очереди команд и цикл выполнения.
- `emulator/bridge.py` — `EmulatorBridge`, запуск процесса BlueStacks, ADB-команды, снимки экрана и ввод.
- `neural_networks/predictor.py` — `Predictor`.
- `neural_networks/detector.py` — `Detector`.
- `neural_networks/context_classifier.py` — `ContextClassifier`.
- `gui/splash_screen.py` и `gui/dashboard.py` — интерфейс загрузки и панель управления.
- `tools/trainer.py` — сбор обучающих примеров «кадр — клик».

## Что исправлено в cleanup/mainline

1. Точка входа импортировала несуществующие имена `ActionPredictor`, `ObjectDetector` и `TaskScheduler`; импорты приведены к реально объявленным классам.
2. Планировщик теперь запускается при инициализации и останавливается после закрытия панели.
3. Работа Tkinter перенесена в главный поток приложения.
4. `Predictor._log_prediction` использует модуль `time`, который ранее импортировался только локально в другом методе.
5. Захват PNG через ADB выполняется в бинарном режиме через `exec-out screencap -p`; текстовое декодирование бинарного кадра удалено.
6. Главный README обновлён: теперь он описывает реальные каталоги и не обещает наличие отсутствующих моделей или тестов.

## Экспериментальная архитектура

Каталог `src/` оставлен без удаления и обозначен как ранний вариант. Он содержит собственные реализации `BotCore`, `Orchestrator`, `Screenshotter`, GUI, менеджера BlueStacks и тренера. Они отличаются от корневых модулей и требуют отдельного сравнения перед переносом. Не удаляйте их только потому, что имена похожи.

## Состояние моделей

Папка `models/` содержит только placeholder. Поэтому:
- ONNX-инференс нельзя считать проверенным;
- формат выходного тензора в `neural_networks/detector.py` должен быть проверен на фактическом файле модели;
- отсутствие весов не должно описываться как успешно загруженная модель.

## Проверки перед релизом

На Windows с установленными зависимостями выполнить:

```powershell
python -m compileall -q .
python main.py
```

Затем отдельно проверить запуск BlueStacks, ADB screenshot, координаты нажатий и реальный формат ONNX. Тесты и CI пока не добавлены; нельзя заявлять о прохождении тестового набора, пока он не создан и не выполнен.
